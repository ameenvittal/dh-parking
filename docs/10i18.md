# 10. Internationalisation

## 1. Setup

- i18next + react-i18next + i18next-browser-languagedetector.
- Languages: `en` (fallback), `ml`.
- Namespaces (one JSON file per namespace per language): `common`, `driver`, `gate`, `zone`, `admin`, `map`, `reports`, `errors`.
- Detection order: `localStorage` (`eventpark.lang`), then the driver's `preferred_language` from `driver-login`, then staff `profiles.preferred_language`, then `navigator.language`, then `en`.
- On change: set `document.documentElement.lang`, store in localStorage. For staff also update `profiles.preferred_language` through RPC `set_my_language(p_lang text)` (all staff roles; add to migration `rpc_visits`).
- Loading: bundle `en` and `ml` for `common`, `driver`, `errors` in the main chunk (driver pages must render instantly). Lazy-load the rest with `i18next-resources-to-backend` and dynamic imports: `import(\`../locales/${lng}/${ns}.json\`)`.

## 2. Key rules

- Keys are dot paths by screen and element: `gate.details.plateLabel`, `driver.nav.turnLeftIn`.
- Interpolation with named values: `"turnLeftIn": "Turn left in {{distance}}"`.
- Plurals with i18next suffixes: `"freeCount_one": "{{count}} free"`, `"freeCount_other": "{{count}} free"`. Malayalam uses the same form for both; still provide both keys.
- Enum labels live in `common.enums.<enumName>.<value>`: `common.enums.visitStatus.driver_parked`.
- Error codes live in `errors.<CODE>`.
- Never build sentences by concatenating translated fragments. One key per sentence.
- Plate numbers, slot labels, phone numbers, and zone codes are never translated.
- Zone, gate, and landmark names: show `name_ml` when language is `ml` and it is not empty, else `name`. Helper `localName(obj, lang)` in `lib/format.ts`.
- Numbers and times format with `en-IN` locale in both languages (Malayalam digits are not used).

## 3. Admin language

Admin screens are fully translated like the rest, but `en` is the default for admins. Reports PDF is English only (see `09-REPORTS.md`).

## 4. Core strings

Translators must review the Malayalam column. Tone: short and polite, plain spoken Malayalam, not formal written style.

## 5. Checks

- CI step `pnpm i18n:check` (script in `scripts/i18n-check.ts`): every key in `en` exists in `ml` and vice versa, no empty values, interpolation variables match between languages.
- ESLint rule `i18next/no-literal-string` (plugin `eslint-plugin-i18next`) on `src/features/**` and `src/components/common/**`, with `jsx-only` mode.
